# Release Engineering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tag `v*` → Forgejo Release with bare-metal tarballs, ghcr images (server + agent), and a Helm chart (OCI + attached) — plus PR-time guards so none of it rots.

**Architecture:** A `scripts/package-release.sh` builds tarballs locally and in CI identically; two Dockerfiles under `deploy/docker/`; a chart under `deploy/chart/argus/`; `release.yml` with three jobs (artifacts→medium, images→large, chart→small) gated on a tag/Cargo.toml version match; cheap chart/docker checks join PR CI.

**Tech Stack:** Forgejo Actions, docker buildx (large runner), cargo-chef base image, helm 3 (OCI), Forgejo Release API via the workflow token.

**Design of record:** `docs/superpowers/specs/2026-07-29-release-design.md`.

## Global Constraints

- Version truth: workspace `Cargo.toml` `version` (currently `0.1.0`); release refuses tag ≠ `v<version>`.
- Frontend tooling is pnpm + oxlint/oxfmt (`pnpm --dir frontend …`); pnpm installed via `npm i -g pnpm@11.17.0` in CI (no corepack).
- Agent artifacts are musl-static with the `file … | grep -qi static` assertion — same as ci.yml's agent-musl job.
- ghcr auth: `GHCR_USER`/`GHCR_TOKEN` Forgejo secrets (operator provides; pipeline must fail with a CLEAR message if absent, not a cryptic docker error).
- The chart never templates secret VALUES — `existingSecret` reference only.
- mTLS gRPC Service is LoadBalancer, never behind an HTTP proxy (PRD §2.4).
- Gates: existing cargo/pnpm gates stay green; `helm lint` + `helm template` (helm may need installing locally: check `which helm`, else download the static binary into the scratchpad — do NOT install system-wide); `python3 -c "import yaml; yaml.safe_load(...)"` for workflow files. Never `cargo test --workspace -- --ignored`.

Agent variant also `install -d /var/lib/argus-agent`.

- [ ] **Step 4: `scripts/package-release.sh`** — the single packaging truth (CI calls exactly this):

```bash
#!/usr/bin/env bash
# Builds the two release tarballs into dist-release/. Used by release.yml
# and runnable locally: scripts/package-release.sh <version>
set -euo pipefail
VERSION="${1:?usage: package-release.sh <version, e.g. 0.1.0>}"
ROOT="$(git rev-parse --show-toplevel)"
OUT="$ROOT/dist-release"
rm -rf "$OUT" && mkdir -p "$OUT"

# Server: embedded frontend first, then release build.
npm install -g pnpm@11.17.0 >/dev/null 2>&1 || true
pnpm --dir "$ROOT/frontend" install --frozen-lockfile
pnpm --dir "$ROOT/frontend" run build
cargo build --release -p argus-server

# Agent: static musl, asserted.
rustup target add x86_64-unknown-linux-musl
cargo build --release -p argus-agent --target x86_64-unknown-linux-musl
AGENT_BIN="$ROOT/target/x86_64-unknown-linux-musl/release/argus-agent"
file "$AGENT_BIN" | grep -qi 'static' || { echo "ERROR: agent not static"; exit 1; }

stage() { # name, binary, unit, env_example, install_sh
  local dir="$OUT/$1-$VERSION"
  mkdir -p "$dir"
  cp "$2" "$dir/"
  cp "$ROOT/deploy/packaging/$3" "$dir/"
  cp "$ROOT/deploy/packaging/$4" "$dir/"
  cp "$ROOT/deploy/packaging/$5" "$dir/install.sh"
  chmod +x "$dir/install.sh"
  tar -C "$OUT" -czf "$OUT/$1-v$VERSION-$6.tar.gz" "$(basename "$dir")"
  rm -rf "$dir"
}
stage argus-server "$ROOT/target/release/argus" argus.service argus.env.example install-server.sh x86_64-linux-gnu
stage argus-agent  "$AGENT_BIN" argus-agent.service agent.env.example install-agent.sh x86_64-linux-musl
( cd "$OUT" && sha256sum ./*.tar.gz > SHA256SUMS )
ls -la "$OUT"
```

- [ ] **Step 5: Verify locally** — run `scripts/package-release.sh 0.1.0`; extract both tarballs to a temp dir; check contents (binary, unit, env example, executable install.sh); `bash -n` both install scripts. Add `dist-release/` to `.gitignore`.

- [ ] **Step 6: Commit** — `git commit -am "feat(release): packaging assets and tarball script"`

- [ ] **Step 1: `Dockerfile.server`** (context = repo root):

```dockerfile
# --- frontend ---
FROM node:22-slim AS frontend
RUN npm install -g pnpm@11.17.0
WORKDIR /app/frontend
COPY frontend/package.json frontend/pnpm-lock.yaml frontend/pnpm-workspace.yaml ./
RUN pnpm install --frozen-lockfile
COPY frontend/ ./
RUN pnpm run build

# --- rust, cargo-chef for layer caching ---
FROM lukemathwalker/cargo-chef:latest-rust-1 AS chef
WORKDIR /app
FROM chef AS planner
COPY . .
RUN cargo chef prepare --recipe-path recipe.json
FROM chef AS builder
COPY --from=planner /app/recipe.json recipe.json
RUN cargo chef cook --release --recipe-path recipe.json -p argus-server
COPY . .
COPY --from=frontend /app/frontend/dist /app/frontend/dist
RUN cargo build --release -p argus-server

# --- runtime ---
FROM debian:bookworm-slim AS runtime
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates curl \
    && rm -rf /var/lib/apt/lists/* \
    && useradd --system --no-create-home argus
COPY --from=builder /app/target/release/argus /usr/local/bin/argus
USER argus
EXPOSE 8080 9443
HEALTHCHECK --interval=30s --timeout=3s CMD curl -sf http://localhost:8080/healthz || exit 1
ENTRYPOINT ["/usr/local/bin/argus"]
```

(cargo-chef cook needs frontend/dist to exist for rust-embed at the FINAL build only — the cook step compiles dependencies without the crate's own build script consuming dist; if `cargo chef cook` fails because rust-embed's build script wants dist, create an empty `frontend/dist/.keep` before cook and overwrite after — determine empirically and document in the Dockerfile.)

- [ ] **Step 5: PR-time guard in ci.yml** — new job:

```yaml
  docker-build:
    runs-on: large
    if: ${{ github.event_name == 'pull_request' }}
    container:
      image: catthehacker/ubuntu:act-24.04
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Detect docker/package changes
        id: filter
        run: |
          git fetch origin ${{ github.base_ref }} --depth=1
          if git diff --name-only origin/${{ github.base_ref }}...HEAD | grep -qE '^(deploy/docker/|\.dockerignore|Cargo\.(toml|lock)|crates/|frontend/)'; then
            echo "changed=true" >> "$GITHUB_OUTPUT"
          else
            echo "changed=false" >> "$GITHUB_OUTPUT"
          fi
      - name: Build images (no push)
        if: steps.filter.outputs.changed == 'true'
        run: |
          docker build -f deploy/docker/Dockerfile.server -t argus:ci .
          docker build -f deploy/docker/Dockerfile.agent -t argus-agent:ci .
```

(Verify the large runner exposes the docker daemon to job containers — if `docker build` can't reach a daemon from inside the job container, run this job directly on the runner host (`runs-on: large` without `container:`) — determine empirically, document in the workflow comment.)

- [ ] **Step 2: values.yaml** (documented, public-consumer quality):

```yaml
image:
  repository: ghcr.io/CHANGEME/argus
  tag: ""            # defaults to appVersion
  pullPolicy: IfNotPresent

# All runtime config arrives via an EXISTING Secret (never templated from
# values -- secrets in Helm release history are forever). Create it with:
#   kubectl create secret generic argus-env \
#     --from-literal=ARGUS_DATABASE_URL=postgres://... \
#     --from-literal=ARGUS_FIELD_KEY="$(openssl rand -base64 32)" \
#     --from-literal=ARGUS_OIDC_ISSUER=... (etc.)
existingSecret: argus-env

http:
  port: 8080
grpc:
  port: 9443
  # MetalLB-pinned address for the agent mTLS endpoint. mTLS terminates in
  # the pod; putting an HTTP proxy in front breaks client-cert verification
  # (PRD 2.4) -- this stays a LoadBalancer.
  loadBalancerIP: ""

ingress:
  mode: none         # none | traefik | ingress
  host: argus.example.com
  # traefik mode also renders a cert-manager Certificate:
  certManager:
    issuerRef:
      name: letsencrypt
      kind: ClusterIssuer

resources: {}
nodeSelector: {}
tolerations: []
```

### Task 4: release.yml

**Files:**
- Create: `.forgejo/workflows/release.yml`

- [ ] **Step 1:** Triggers: `on: push: tags: ["v*"]` plus `workflow_dispatch` with a `dry_run` boolean input (default true) — dispatch builds everything, publishes nothing.

- [ ] **Step 2: job `artifacts` (medium, rust container).** Steps: checkout; version check:

```bash
TAG="${GITHUB_REF_NAME#v}"
CARGO_V=$(grep -m1 '^version' Cargo.toml | cut -d'"' -f2)
[ "$TAG" = "$CARGO_V" ] || { echo "tag v$TAG != Cargo.toml $CARGO_V"; exit 1; }
```

(dispatch dry-run: skip the check, use `0.0.0-dry`); `scripts/package-release.sh "$VERSION"`; create the Forgejo Release + upload attachments via the API using the workflow's own token (`secrets.GITHUB_TOKEN` — verify the Forgejo Actions token has release scope on this instance; if not, a dedicated `RELEASE_TOKEN` secret, documented in RELEASING.md):

```bash
curl -sf -X POST "$GITHUB_SERVER_URL/api/v1/repos/$GITHUB_REPOSITORY/releases" \
  -H "Authorization: token $TOKEN" -H "Content-Type: application/json" \
  -d "{\"tag_name\":\"$GITHUB_REF_NAME\",\"name\":\"$GITHUB_REF_NAME\",\"body\":$NOTES_JSON}" | tee release.json
RID=$(python3 -c "import json;print(json.load(open('release.json'))['id'])")
for f in dist-release/*; do
  curl -sf -X POST "$GITHUB_SERVER_URL/api/v1/repos/$GITHUB_REPOSITORY/releases/$RID/assets?name=$(basename "$f")" \
    -H "Authorization: token $TOKEN" -F "attachment=@$f"
done
```

Notes body: `git log --oneline <prev-tag>..HEAD` JSON-escaped via python3. All publish steps guarded by `if: ${{ github.event_name == 'push' }}` (tags only).
